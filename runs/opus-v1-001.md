## Headless adapter

`acceptance/adapters/opus-v1-001.mjs` imports the submission's own `World`, `PilotRunner`,
`settle`, `ScriptedPilot`, `PromptPilot`, `mockCallModel` and `observe` unchanged from the
execution copy through Node's native TypeScript type stripping (no bundler, no rewrite; the
submission has no esbuild, and its own `npm run sim` uses the same mechanism). **Artificial
scheduler (disclosed):** each simulated frame is `world.step()` (50 ms tick), `runner.onTick(world)`
(10-tick pilot cadence) and the submission's own `settle()` (six microtask turns) — exactly the loop
its browser `frame()` and `scripts/sim.ts` run. Scripted pilots receive `world.rng.fork(100 + i)`
as the browser gives them.

Each match started with six bearbots, twelve towers and two nexuses. Minion waves appeared on all
three lanes at 5 s and every 30 s after; minions moved and took damage every wave. Bearbots die
within the first ten seconds on every seed (the mid bears meet at once, towers hit for 100) and

green's nexus at 0 hp and violet's at 1,590. Of the 37 + 35 recalls started only 8 + 7 completed a
teleport; most were cancelled by damage or the bear died first. The seed-1 match completed 4,036
logged pilot decisions.

**Replay.** The seed-1 action log was re-applied to a bare `World` with no pilots at the recorded
ticks: per-tick normalized state trace and end state were identical to the original run
(`traceEqual: true`, `endStateEqual: true`). The repeated seed-1 run also matched. The first is
log-based replay evidence; the second is repeatability under the adapter scheduler only.

mockCallModel)`: 685 decisions, 0 parse errors, action kinds attack 440 / move 129 / hold 53 /
recall 41 / ability 22; the first prompt starts with the persona file and embeds the observation in
a fenced JSON block. The mock heuristic differs from the seeded scripted one, so the match diverged
(08:25, violet) while still ending by nexus kill.

**Delayed-reply probe.** An external pilot returned the scripted decision only 60 ticks (3 s) after
being asked: in all four recorded windows the clock advanced 61 ticks, the bear kept its standing
order for 61/61 ticks, was not re-asked while pending, and the delayed decision was applied the tick
after release. This is the non-blocking contract, not real HTTP timing.

**Timeout probes** (external pilots only; no timer or game code changed): six always-hold pilots →
10:00, `time: more towers standing`, green (minions alone razed two violet outer towers at 05:03
and 08:06). Violet scripted for 60 s then home, green hold → 10:00, towers 4/2, violet by
`time: more towers standing`. All six scripted until 5:00 then home → 10:00, towers 4/1, violet by
the same rule. Every timeout fired at exactly 10:00 with both nexuses alive; the nexus-hp
tiebreak and the dead-even draw were not reached in any probe and are present in
`World.checkEnd()` by source only.

**Ability casts (seed 1).** Detected by the ready-tick moving forward; minimum repeat by one bear vs

## What is and is not established

Established on this specimen: a fresh default Scripted 3v3 reaches a destroyed nexus on every seed
tried (5 distinct seeds, 07:02–09:56), first blood happens within ten seconds, recalls are frequent
and mostly interrupted, the action log replays to an identical state, the mock and HTTP prompt
paths compose persona + observation and apply parsed replies without blocking the sim, the browser
match matches the adapter tick-for-tick at both speeds, and the timeout fallback fires at 10:00
with the "more towers standing" branch observed three times.

Not established: anything visual (arena layout, river/jungle/minimap, palette, legibility, that the
canvas is not empty) — screenshots exist but no human confirmed them; the nexus-hp and dead-even
timeout branches; malformed-reply recovery; behaviour under real network latency. Six matches on
one specimen are not a statistical claim about the model.
