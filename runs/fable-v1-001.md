## Headless adapter

`acceptance/adapters/fable-v1-001.mjs` imports the submission's own `Sim`, `Match`, `ScriptedPilot`,
`PromptPilot` and `mockModel` unchanged from the execution copy through Node's native TypeScript
type stripping (no bundler, no rewrite). **Artificial scheduler (disclosed):** each simulated frame
is `match.step()` — the submission's 50 ms tick plus its 10-tick pilot cadence — followed by a full
`setImmediate` flush, so a decision that resolves in that frame lands before the next tick. That is
the browser at 1× (one step per animation frame); above 1× the browser batches several steps per
frame without flushing, which the adapter does not reproduce (see the browser section). Team A is
reported as violet and team B as green, as the submission's own UI labels them.

## What is and is not established

Established on this specimen: a fresh default Scripted 3v3 reaches a destroyed nexus on every seed
tried (5 distinct seeds, 04:31–09:30), first blood happens within the first minute, recalls are
frequent but do not stall the match, the action log replays to an identical state, the mock and
HTTP prompt paths compose persona + observation and apply parsed replies without blocking the sim,
and the timeout fallback fires at 10:00 with the nexus-hp and dead-heat branches observed.

Not established: anything visual (arena layout, river/jungle/minimap, palette, legibility, that the
canvas is not empty) — screenshots exist but no human confirmed them; the "more towers standing"
timeout branch; malformed-reply recovery; behaviour under real network latency; the 4× browser
loop's frame-timing dependence is noted but not characterised. Six matches on one specimen are not
a statistical claim about the model.
