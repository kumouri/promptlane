# Jev vs qwen/qwen3-32b, same intent: results, 2026-09-23 → 09-25

Ceryce's ask (2026-09-23 ~14:57 CT): *"write a qwen team prompt and a jev team prompt and test them
against each other. The prompts don't have to be the SAME but they should encode the same intent
so the test is more a model test than a prompt test."* Started 2026-09-23 as margo job
20260923-195911-4740; the host crashed mid-run and the job was resumed and finished 2026-09-25.

- **Intent (source of truth):** `docs/jev-vs-qwen32b-intent.md` — one cascade, engage-before-
  positioning, per-instrument recall thresholds.
- **qwen team:** `prompts/pilots/team-qwen.md`, played by `qwen/qwen3-32b` on OpenRouter
  (DeepInfra, `think: false`, temperature 0.2) through the game's own frozen `PromptPilot`.
- **Jev team:** `tools/jev/team_rules.py` questions via `tools/jev/team_server.py` → Cloudflare
  Workers AI `typesafe/jev`, cascaded and turned into actions in code (`tools/match/jevTeamPilot.ts`).

## Answer

**Jev plays the shared intent far more faithfully than qwen3-32b, and wins because of it.** Over
10 clean jam-shape matches, Jev won 8, qwen won 0, and 2 were drawn. Offline, Jev's cascade matched
the intent's ground truth on 263/263 scenarios; qwen's prose reply matched on 95/263 (36.1%). The
in-game gap has the same cause as the offline one: qwen mostly walks home or holds when the intent
says fight or push, so it barely fights (523 attacks+abilities vs Jev's 2,240) and loses a tower in
8 of 10 matches.

This says more about which model follows the intent than about which model plays better; see
"What this does not show".

**Reading the numbers.** Jev dies a lot (19 vs 2) because it follows rule 2 and fights whatever
is in front of it. On violet it dies exactly 3 times in every match, but takes a green tower
first. qwen seldom dies because it seldom fights, and it never presses its advantage: 7 recalls
and 793 holds in total, with no push to trade back for the tower. It wins the attrition and loses
the match. Seed 6 is the one match where qwen fought (338 attacks+abilities), and it still lost a
tower.

## What this does not show

- **Not a play-strength ranking.** Every win is one tower on the timeout tiebreak against an
  opponent that rarely engages. Jev beat a passive opponent. Against a team that punishes its
  deaths, 19 deaths in 10 matches would matter.
- **The sample is smaller than 10.** The matches are close to deterministic. Seeds 1, 5, 7 and 9
  (Jev on violet) give nearly identical results: 3 Jev deaths, one qwen tower, and about 162–187
  Jev attacks each time. Treat this as about two situations (one per side), each repeated, not 10
  independent draws.
- **Jev never picks targets.** Per the intent doc's "can't be matched" table, code picks the
  target for Jev (lowest-HP bearbot, else nearest minion), and Jev only decides whether to engage.
  qwen has to do both. This result rarely turns on that, though: qwen's misses are almost all
  "didn't engage", not "engaged the wrong thing".
- **One prompt, one model setting.** qwen3-32b ran with thinking off and temperature 0.2, on one
  prose encoding. A different wording might close some of the 36% gap. That is a prompt test, not
  this model test.
- **Violin's finishing ability** is never exercised offline, because the logs carry no foe HP
  (documented in `team_compliance_scenarios.py`). This limits both models equally.

## Crash and outage record: what was run, what was thrown out

| file | seeds | status |
|---|---|---|
| `runs/jev-vs-qwen32b-2026-09-23.json` | 1–6 | seed 1 **kept**; seeds 2–6 **excluded**: every Jev call after the first ~90 of seed 2 got `workers-ai 401 Authentication error` (the wrangler OAuth token expired about an hour in), so Jev never played |
| `runs/jev-vs-qwen32b-seed2-3.json` | 2–3 | re-run of 2–3 before the crash, **kept** |
| `runs/jev-vs-qwen32b-seed4-10.json` | 4–10 | run 2026-09-25; seed 7 **excluded** (401 again from tick 6146, 147/596 Jev calls). `wrangler whoami` only refreshes a token that has *already* expired, so a token with a few minutes left survived the pre-match refresh |
| `runs/jev-vs-qwen32b-seed7-rerun.json` | 7 | clean re-run, **kept** |

`merge_team_bench.mjs` excludes a match when over 10% of its Jev calls failed at the transport. It
keeps isolated failures: seed 4 had 1 Jev error in 876 calls, and the pilot holds for that one
decision. The host crash itself damaged nothing that survived: every JSON file parses and carries
its summary. The only compliance result redone is qwen's, because the pre-crash file recorded
`predicted: null` with no reply, which could not tell a model miss from a scorer miss. The redo
records the raw reply and agrees with it within 2 points (36.1% vs 38.0%).

**For the next run:** restart `team_server.py` with a token that has at least a match's worth of
life left (check `expiration_time` in wrangler's `default.toml`), not just after `whoami`.
